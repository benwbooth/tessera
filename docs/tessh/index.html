tessh guide

tessh is a shell language that is Python underneath. You write it like a shell: one command per line, words separated by spaces, no commas and no call parentheses. Every line compiles to Python, so all of Python and every Python library work in it. Indentation gives the structure.

print hello world
name = tessh
print "hi from $name"
echo a program runs too
hello world
hi from tessh
a program runs too

help TOPIC shows a topic, for example help pipes. help $obj shows Python's help for a value, such as help $str.split. Every example here is checked: the output under it is what it printed.

Words and values

Words

A bareword is text without quotes. As an argument it's the string it spells. Flags, paths, globs and file names are all barewords.

print hello -a --all --color=auto ./run.sh ../x /etc/hosts foo.txt g++
x = hello
print (type $x).__name__ $x
hello -a --all --color=auto ./run.sh ../x /etc/hosts foo.txt g++
str hello

A backslash takes the next space or special character into the word, as in a shell: 7th\ Heaven/, \$5, a\;b, \* (not a glob). At the end of a line it carries the line on to the next.

print 7th\ Heaven/ \$5 a\;b \*
echo one \
  two
7th Heaven/ $5 a;b *
one two

Operator characters glued to other text are part of the word. Spaced, they're operators.

print -la *.nothing a+b c++
print (1 + 2)
-la *.nothing a+b c++
3

A bareword written as a path — starting with /, ~, ./ or ../ — is a Path: a pathlib path, so $p.name, $p.parent, $p / more and $p.exists work. It keeps how it was written, which is what a command, print and "$p" get, and ~ is your home. + joins it as text; Path 'x y' makes one from text.

p = /tmp/notes/todo.txt
print (type $p).__name__ $p.name $p.parent $p.suffix ($p / more)
r = ./run.sh
print $r "in $r" ($r + .bak) (Path 'a b' / c)
Path todo.txt /tmp/notes .txt /tmp/notes/todo.txt/more
./run.sh in ./run.sh ./run.sh.bak a b/c

True, False and None are Python's constants.

print True False None
True False None

Numbers

Anything Python reads as a number is one.

print 42 -7 0x1f 0b101 0o17 1_000 2.5e3 3j
print (type 2.5).__name__ (type 42).__name__
42 -7 31 5 15 1000 2500.0 3j
float int

Strings

Double quotes interpolate $name, $(form) and ${expr} and understand the usual escapes. Single quotes are raw: no escapes and no interpolation.

name = world
n = 3.14159
print "hello $name"
print "two plus two is $(2 + 2)"
print "pi is ${n:.2f}"
print "tab:\t| newline escaped: \\n | dollar: \$name"
print 'raw: $name \n'
hello world
two plus two is 4
pi is 3.14
tab:	| newline escaped: \n | dollar: $name
raw: $name \n

${…} takes any expression, a !r or !s conversion and a format spec, as f-strings do. Use it to glue text right after a variable.

items = [a b]
file = notes
print "${file}.txt" "${items!r}" "${len $items}"
notes.txt ['a', 'b'] 2

Triple quotes span lines. b"…" is bytes and r"…" a raw string.

text = """one
two"""
print $text
print b"bytes" r"raw\n"
one
two
b'bytes' raw\n

Variables

$name is the variable name. Attribute access, indexing and slicing glue on.

xs = [10 20 30 40]
d = {k: v}
print $xs[0] $xs[1:3] $xs[-1] $d[k]
print $xs.__len__ ("a,b".split ",")
10 [20 30] 40 v
<method-wrapper '__len__' of list object at ADDR> ['a' 'b']

Call a method by giving it its arguments, or by putting it alone on a line or alone in parentheses.

s = "Hello"
print ($s.upper) ($s.replace l L) ($s.count l)
HELLO HeLLo 2

A $name that isn't a Python name is the environment variable, and $? is the last command's exit status.

export GREETING=hey
print $GREETING
false
print $?
true
print $?
hey
1
0

Glued text joins into one word: $HOME/src, out-$n. After a variable a glued .name is an attribute, so write ${n}.log for "n, then .log".

n = 7
print out-${n}.log file_$n
out-7.log file_7

Calls and structure

Calls

A call is the function then its arguments, spaced: f a b c.

def add a b
  $a + $b
print (add 1 2)
print (max 3 9 4)
3
9

Applying a function binds tighter than any operator, as in Haskell. Wrap a calculation in parentheses to pass its value.

n = len [1 2] + 1         # (len [1 2]) + 1
print $n (len [1 2 3]) ((len [1 2]) * 10)
3 3 20

So print $x + 1 is (print $x) + 1: write print ($x + 1).

Keyword arguments are name=value, glued. *$xs and **$kw splat.

print a b c sep=-
args = [1 2 3]
opts = {sep: "/"}
print *$args **$opts
a-b-c
1/2/3

A function with no arguments is called when it stands alone on its line or alone in parentheses.

import os
here = (os.getcwd)
print ((len $here) > 0)
True

Indented lines under a call are more arguments, one per line.

print
  one
  two
  sep=", "
one, two

An operator at the head of parentheses applies it Lisp-style.

print (+ 1 2 3) (- 10 4) (- 5) (* 2 3 4)
6 6 -5 24

Lines

Each line is a form. ; separates forms on one line, a trailing \ or an open bracket continues a line, and # starts a comment.

a = 1 ; b = 2   # two forms on one line
total = $a + \
  $b
nums = [1 2
        3 4]
print $total $nums
3 [1 2 3 4]

Commas separate only when a space, a bracket or the end follows. Inside words they're text.

print [1, 2] cut-f1,3
[1 2] cut-f1,3

Indent with spaces; tabs are an error. elif, else, except and finally continue the form above them at the same indentation.

Operators

Python's operators, spaced, with Python's precedence. Comparisons chain.

import operator
x = 4
print (1 + 2 * 3 ** 2) (7 // 2) (7 % 3) (2 ** 10) (7 / 2)
print (1 < $x < 5) ($x in [1 4]) ($x not in [1]) ($x is None) ($x is not None)
print (5 & 3) (5 ^ 3) (1 << 4) (256 >> 2) (operator.invert 5)
print (True and False) (True or False) (not True)
print (True && False) (True || False) (! False)
19 3 1 1024 3.5
True True True False True
1 6 16 64 -6
False True False
False True True

From the loosest to the tightest: || or, && and, not !, |, comparisons, backtick and custom operators, ^, &, << >>, + -, * / // % @, prefix -x +x, **, application, then glued .attr and [i]. (~ is your home folder and a macro's unquote, so bitwise not is operator.invert.)

Prefix minus: spaced, or glued to a variable or a bracket.

x = 5
print (- $x) -$x -(2 + 1)
-5 -5 -3

if … then … else … is the conditional expression, and := works inside parentheses.

n = 12
print (if $n > 10 then big else small)
if (m := $n * 2) > 20
  print $m
big
24

In a command, operators other than the shell's are words.

echo 1 + 2 is three
1 + 2 is three

Custom operators

Backticks make any function infix.

print (3 `max` 9) ([1] `list.__add__` [2])
9 [1 2]

defop defines a symbolic operator: its precedence (1 loosest to 13 tightest, 6 is the custom level), its associativity (left, right or none) and its function.

def concat a b
  $a + $b
defop <> 6 left concat
def power a b
  $a ** $b
defop ^^ 12 right power
print ([1] <> [2] <> [3]) (2 ^^ 3 ^^ 2)
[1 2 3] 512

Commands

Commands

A line whose first word isn't a Python name runs a program. Its arguments are words: barewords, $values, (forms).

echo hello from echo
name = tessh
echo hi $name (1 + 1)
hello from echo
hi tessh 2

A command on a line of its own is attached: its output goes straight to the terminal. Used as a value, it's captured: you get its output as text, without the final newline.

who = echo captured
print got $who
out = printf "a\nb\nc\n"
print $out.lines
got captured
['a' 'b' 'c']

What a command returns is an Output: a str with .code (the exit status), .ok and .lines. Its truth is the exit status. Errors it prints go to the terminal; 2>&1 captures them too.

r = sh -c "echo out; exit 3"
print $r $r.code $r.ok (bool $r)
ok = (true)
print (bool $ok) $ok.code
both = sh -c "echo out; echo err >&2" 2>&1
print $both.lines
out 3 False False
True 0
['out' 'err']

A list inserts one argument per item. Quoted strings aren't split.

args = [one two]
printf "<%s>" $args
echo
printf "%s|" "a b" c
echo
<one><two>
a b|c|

\name runs the program even when a Python function has that name.

def echo *words
  print python echo
echo x
\echo program echo
python echo
program echo

A name tessh doesn't know is looked up when it runs, so functions defined in other ways still work. Your own function reads its arguments as words, globs included, with @command.

@command
def shout *words
  print (str.upper (' '.join $words))
shout hello *.nothing-matches
HELLO *.NOTHING-MATCHES

Globs

*, ? and […] in a command's words expand to the matching names, sorted. No match leaves the word as written. ~ at the start is your home folder.

touch a.py b.py c.txt
echo *.py
echo ?.txt
echo *.none
print (glob *.py)
print ((echo ~/x) == "$HOME/x")
a.py b.py
c.txt
*.none
['a.py' 'b.py']
True

To Python, a pattern written bare is a Glob. There's no glob object in Python itself (glob.glob and Path.glob are functions), so tessh has its own. Iterating it gives the matching paths, sorted and read again each time. len, in and [i] work, and printed (or in "$g") it's the names, as echo shows them. Quote a pattern to keep it text: '*.py'.

touch a.py b.py
g = *.py
print $g (len $g) ([$p.stem for p in $g]) (repr $g)
f = ./a.py
print ($f in $g) $g[0] "found: $g"
a.py b.py 2 ['a' 'b'] Glob('*.py')
True a.py found: a.py b.py

Regexes

re'…' (or re"…") is a regular expression: raw, so \d means a digit, compiled once. Perl's flags go after it: i ignores case, m makes ^ and $ match at every line, s lets . match a newline, x allows spaces and comments, a keeps \w to ASCII. It's Python's re.Pattern, so .sub, .findall, .split and the re module all work with it.

=~ matches and !~ doesn't. What it does depends on what's on the right:

  • a regex (re'…'): searched for anywhere in the text; the match (with its groups) or None.
  • a glob (an unquoted word with wildcards, *.py): whether the whole name or path fits it; True or False.
  • anything else, such as quoted text: whether the text has it in it, as is ($, ., * mean themselves); True or False.
line = "Build 42 ok"
m = $line =~ re'(\d+)'
print ($m.group 1) ($m.start 1) ($line !~ re'^\d+$')
print (bool ($line =~ re'^build'i)) (bool ($line =~ re'^build'))
f = ./main.py
print ($f =~ *.py) ($f !~ *.rs)
if $line =~ re'ok$'
  print done
print ($line =~ 'ok') ($line =~ 'ok$')
print (re'o'.sub '0' $line) re'\w+'i
42 6 True
True False
True True
done
True False
Build 42 0k re'\w+'i

Pipes

| pipes one program's output into the next, as in a shell.

printf "b\na\nc\n" | sort | head -2
n = printf "x\ny\n" | wc -l
print lines: ($n.strip)
a
b
lines: 2

A stage can be a Python call. It gets what came before as its last argument: the text, or the earlier Python value itself.

echo hello | str.upper | print
print (printf "3\n1\n2\n" | str.split | sorted)
import json
echo '{"a": [1, 2]}' | json.loads | print
HELLO
['1' '2' '3']
{a: [1 2]}

The first stage can be a value: a string is written as it is and any other iterable one item per line.

text = "one two three"
$text | wc -w
[c b a] | sort
3
a
b
c

When the right side is a value rather than a program or function, | is Python's bitwise or.

print ({1 2} | {2 3}) (5 | 2)
a = {x: 1}
b = {y: 2}
print ($a | $b)
{1 2 3} 7
{x: 1 y: 2}

And, or, then

&& runs the next command if the last one succeeded, || if it failed, ; either way.

true && echo yes
false && echo never
false || echo fallback
false ; echo anyway
yes
fallback
anyway

Python code fails with an exception rather than a status. &&? and ||? count one as a failure, and a parenthesized command or expression with ? or ! after it converts between the two: (expr)? makes an exception a false value, and (cmd)! makes a failed command an exception (see Errors).

Redirections

They're bash's. >f writes, >>f appends, >|f writes even over a file (tessh has no noclobber), <f reads and <>f opens for both. A number in front picks the file descriptor (2>f, 2>>f, 3>f, 0<f); &>f and &>>f (or >&f) take output and errors both. 2>&1 makes errors go where output goes, >&2 the other way, 3>&1 and 0<&3 copy any, and 2>&- closes one. They're done left to right, as in bash: >f 2>&1 puts both in the file, 2>&1 >f sends errors where output went before. Glued to the file they work anywhere, Python calls included (descriptors 0, 1 and 2 there); spaced (> f) they work in commands.

echo first >out.txt
echo second >> out.txt
print from python >>out.txt
cat <out.txt
sh -c "echo oops >&2" 2>err.txt
cat err.txt
sh -c "echo both >&2" 2>&1 | tr a-z A-Z
sh -c "echo o; echo e >&2" &>all.txt
sh -c "echo e2 >&2" 2>>all.txt
cat all.txt
echo to-stderr >&2 2>/dev/null
sh -c "echo three >&3" 3>&1
sh -c "echo gone >&2; true" 2>&-
first
second
from python
oops
BOTH
o
e
e2
three

<<<word gives a program the word (and a newline) as its input. A heredoc, <<END, gives it the lines up to one that's just END; $name and $(…) in them are filled in, unless the word is quoted (<<'END'), and <<-END takes the tabs off the front of each.

tr a-z A-Z <<<hello
name = world
cat <<END
hi $name
  kept as is
END
cat <<'END'
$name stays
END
HELLO
hi world
  kept as is
$name stays

<(…) and >(…) with something run in them (a program, a command, a function called) are process substitution, as in bash: a path that reads what it prints (a function's printing, then what it gives back), or that it reads what's written to. With a value in them (>$f, >("out" + ".txt")) they're the file it names.

diff <(printf "a\nb\n") <(printf "a\nc\n")
echo split | tee >(tr a-z A-Z) >/dev/null
def numbers
  print 1
  print 2
paste <(numbers) <(printf "a\nb\n")
2c2
< b
---
> c
SPLIT
1	a
2	b

Jobs

A trailing & runs a command in the background, and its value is a Job. jobs lists them, fg brings one back and bg continues a stopped one. At the REPL, Ctrl+Z stops what's running and Ctrl+C interrupts it.

j = sleep 0.5 &
jobs
fg
print done
[1] running sleep 0.5
done

Environment and folders

export sets environment variables for this shell and the programs it runs, and unset removes them. $env is the environment as a mapping.

export COLOR=blue SIZE=10
sh -c 'echo $COLOR $SIZE'
$env.SIZE = 11
print $env.SIZE $env["COLOR"] ("COLOR" in $env)
unset COLOR
print ("COLOR" in $env)
blue 10
11 blue True
False

NAME=value before a program, as in bash, gives it that variable for just that run; the shell's own environment is as it was after.

SALUTE=hi sh -c 'echo $SALUTE'
print ("SALUTE" in $env)
hi
False

cd changes folder (cd alone goes home, cd - goes back), and pushd, popd and dirs keep a stack. A line that's only a folder (~, /tmp, ../src) goes there, as cd would. They take bash's options: cd -P goes by the real folders (-L, keeping symlinks in the path, is the default), $CDPATH is searched, and pushd/popd/dirs take +N/-N, -n, -v and the rest.

mkdir -p sub/deeper
start = (pwd)
cd sub
print ((pwd).endswith "/sub")
cd deeper
cd ../..
print ((pwd) == $start)
pushd sub >/dev/null
popd >/dev/null
print ((pwd) == $start)
True
True
True

which finds a program: it prints where, and its value is the path.

which git
path = which git

source file.tsh runs a tessh file here, its names kept. A script's arguments are in $argv.

print "x_from_file = 41 + 1" >lib.tsh
source lib.tsh
print $x_from_file
42

Python, written as tessh

Assignment

x = 5
x += 1
x *= 2
[a b] = [1 2]
c, d = 3, 4
[head *rest] = [1 2 3 4]
print $x $a $b $c $d $head $rest
12 1 2 3 4 1 [2 3 4]

Attributes and items are targets too, and del removes.

d = {}
$d[k] = 1
$d["j"] = 2
del $d[k]
import types
o = (types.SimpleNamespace)
$o.name = thing
print $d $o.name
{j: 2} thing

The augmented forms are += -= *= /= //= %= **= @= &= |= ^= <<= >>=.

name=value glued, as bash writes it, is the same as name = value when it starts a line; several on one line are each assigned. Inside a call (f a=1) it's still a keyword argument, and == never assigns. a= with nothing after is the empty string, as in bash (a program given $a gets an empty argument, as bash's "$a" would); a = None is no value, and del a removes the name (unset is for environment variables).

n=5 label=total
n += 1
print $label $n
note=
print [$note] (len $note)
total 6
[''] 0

Functions

def name params… with an indented body. The value of the last form is returned.

def greet who greeting=hi *more punct="!" **extra
  "$greeting, $who$punct" + (str $more) + (str $extra)
print (greet Ben)
print (greet Ben hello x y punct=? z=1)
hi, Ben!(){}
hello, Ben?('x', 'y'){'z': 1}

A one-line def puts the body after =. return leaves early.

def sq x = $x * $x
def first_even xs
  for x in $xs
    if $x % 2 == 0
      return $x
  None
print (sq 7) (first_even [1 3 4 5]) (first_even [1])
49 4 None

fn [params] body is a lambda. A block body works too.

add = fn [a b] ($a + $b)
print ($add 2 3) (list (map (fn [x] ($x * 10)) [1 2]))
pick = fn [x]
  if $x then yes else no
print ($pick 1)
5 [10 20]
yes

Decorators go on the lines before. yield makes a generator.

import functools
@functools.cache
def fib n
  if $n < 2 then $n else (fib ($n - 1)) + (fib ($n - 2))
def count_up n
  for i in (range $n)
    yield $i
print (fib 50) (list (count_up 3))
12586269025 [0 1 2]

global and nonlocal work as in Python.

total = 0
def bump
  global total
  total += 1
bump ; bump
def counter
  n = 0
  def inc
    nonlocal n
    n += 1
    $n
  $inc
c = (counter)
c ; c
print $total (c)
2 3

async def, await, async for, async with and async comprehensions ([$x async for x in $source]) work as in Python. await, async for and async with also work outside a function: in a script, at the prompt and in a notebook cell, as in IPython. There's no need for asyncio.run.

import asyncio
async def twice x
  await (asyncio.sleep 0)
  $x * 2
print (await (twice 21))
async def count n
  for i in (range $n)
    yield $i
print [$i async for i in (count 3)]
42
[0 1 2]

Those lines run on one event loop that lasts the whole session, so a task or client made on one line is still there on the next. A line without an await doesn't run the loop. Start a task with asyncio.ensure_future there, because asyncio.create_task wants a loop that's running. The task runs while a later line awaits something. Ctrl-C cancels what's being awaited. A program run from async code blocks the loop while it runs, as subprocess.run does in Python. Use asyncio.create_subprocess_exec to run programs alongside other tasks.

Conditionals

if is an expression: its value is the branch's.

def sign n
  if $n < 0
    'neg'
  elif $n == 0
    'zero'
  else
    'pos'
print (sign -2) (sign 0) (sign 5)
size = if (len [1 2 3]) > 2 then big else small
print $size
neg zero pos
big

An if block can be a value directly.

n = 7
kind = if $n % 2 == 0
  'even'
else
  'odd'
print $kind
odd

A command as the condition uses its exit status.

if grep -q z <<< "abc"
  print never
if printf "abc" | grep -q b
  print found
found

Loops

for i in (range 3)
  print $i
for [k v] in ({a: 1 b: 2}.items)
  print $k $v
n = 3
while $n > 0
  n -= 1
  if $n == 1
    continue
  print n is $n
for x in [1 2 3]
  if $x == 5
    break
else
  print no five

while takes an else too, run when the loop ends without break.

n = 2
while $n > 0
  n -= 1
else
  print ended at $n

Collections

[1 2 3] is a list; with commas each part is an expression. {a: 1} is a dict with string keys from barewords, {$k: 1} uses a variable. {1 2} is a set, () the empty tuple, (1, 2) a tuple and {} an empty dict.

k = key
print [1 2 3] [1 + 1, 3] {a: 1 b: [2 3]} {$k: 1} {1 2} () (1, 2) {}
xs = (list (range 10))
print $xs[2:5] $xs[::3] $xs[-2:] $xs[:2]
[1 2 3] [2 3] {a: 1 b: [2 3]} {key: 1} {1 2} () (1, 2) {}
[2 3 4] [0 3 6 9] [8 9] [0 1]

print shows a list, dict, set, tuple or record (a dataclass or namedtuple, as (Point x=1 y=2)) as tessh: paste what it prints back in and you get an equal value. One that doesn't fit on a line is laid out over indented lines, and it's colored by type on a terminal or in a notebook (not when piped, or with NO_COLOR). A cell's or the REPL's value is shown the same way. What has no such form, like a function or a file, shows as Python shows it. pretty x gives the text, with width= and color= to choose.

Comprehensions

Written as in Python, inside brackets.

xs = [1 2 3 4]
print [$x * 2 for x in $xs if $x > 1]
print {$x: $x ** 2 for x in $xs}
print {$x % 2 for x in $xs}
print (sum ($x for x in $xs))
print [[$i $j] for i in [1 2] for j in [a b]]
[4 6 8]
{1: 1 2: 4 3: 9 4: 16}
{0 1}
10
[[1 'a'] [1 'b'] [2 'a'] [2 'b']]

As everywhere, a name is bare where it's made (for x) and has $ where it's read ($x, $xs). Python's [x * 2 for x in xs] is an error saying so: a bare x or xs would be the text, and the same goes for a for loop's body.

Classes

class Animal
  def __init__ self name
    $self.name = $name
  def speak self = "$self.name makes a sound"

class Dog Animal
  def speak self = "$self.name barks"

for a in [(Animal cat) (Dog rex)]
  print ($a.speak)
print (isinstance (Dog x) $Animal)
cat makes a sound
rex barks
True

Bases, keywords (metaclass=…), class attributes, annotated fields and decorators work as in Python.

from dataclasses import dataclass
@dataclass
class Point
  x: int = 0
  y: int = 0
print (Point 1 2) (Point y=5)

class Registry type
  names = []
  def __new__ mcs name bases ns
    $mcs.names.append $name
    type.__new__ $mcs $name $bases $ns
class Plugin metaclass=Registry
  pass
print $Registry.names
(Point x=1 y=2) (Point x=0 y=5)
['Plugin']

Errors

Commands fail as in bash, with an exit status: a program (mkdir, ls, grep) and tessh's builtins (cd, pushd, popd, export, which…) alike. || runs what's after it when the command fails, && when it worked, if cmd tests it, and $? holds it. A failing builtin's message goes to standard error, so 2>/dev/null hides it.

cd /no/such/folder 2>/dev/null || print "no such folder, status" $?
mkdir /proc/nope 2>/dev/null || print "mkdir failed too"
if not (cd /no/such/folder 2>/dev/null)
  print "still here"
no such folder, status 1
mkdir failed too
still here

A builtin that fails on a line of its own, where nothing checks it, stops the script with its error, the way a Python error does. Bash would go on in the wrong folder, and a cd build that failed before rm -rf * is how whole home folders go. A program on a line of its own that fails doesn't stop the script, as in bash, unless strict mode is on (strict or set -e, below).

Python code fails with an exception. Put ? after a parenthesized expression to turn one into a value: (expr)? is the expression's value when it works, and a Failed (false, with the exception as .error) when it raises, with $? 1. So || gives a fallback, as it does for a command. A NameError still raises: a misspelled name is a bug, not a failure.

n = (int "42")? || 0
m = (int "forty-two")? || 0
print $n $m
r = (open /no/such/file)?
if not $r
  print "couldn't open:" $r.error.strerror
42 0
couldn't open: No such file or directory

||? and &&? save the parentheses: they're || and && with an exception on their left counted as a failure. a ||? b is (a)? || b, and a &&? b is (a)? && b.

import json
port = int ($env.get PORT "") ||? 8080
print $port
json.loads '{"a": 1}' &&? print "valid JSON"
json.loads "{oops" &&? print never
8080
valid JSON

At the prompt, a Failed isn't shown, as a failed command shows nothing: its ✘ and $? say it failed. Keep it with r = (expr)? to look at $r.error.

As with or, a value that works but is false (0, "", []) also takes the fallback. To tell those apart, keep the value with (expr)? and test isinstance $r $Failed.

For more than a fallback, try catches exceptions by class. It's an expression too.

r = try
  int abc
except ValueError as e
  print caught: $e
  -1
else
  0
finally
  print cleanup
print $r
caught: invalid literal for int() with base 10: 'abc'
cleanup
-1

raise, raise … from … and assert:

def check n
  assert ($n > 0) "n must be positive"
  $n
try
  check 0
except AssertionError as e
  print $e
try
  raise (ValueError bad)
except ValueError as e
  print got $e.args
n must be positive
got ('bad',)

raise X from Y chains, a bare except catches anything, and several classes go in a tuple.

try
  try
    1 / 0
  except ZeroDivisionError as e
    raise (ValueError "wrapped") from $e
except (KeyError, ValueError) as e
  print $e "<-" (type $e.__cause__).__name__
try
  int not-a-number
except
  print "anything goes"
wrapped <- ZeroDivisionError
anything goes

Where Python wants a class (after except, as a base), a bareword is the name. Elsewhere pass a class with $: isinstance $x $int.

! goes the other way from ?: put it after a parenthesized command or expression, (cmd)! or $(cmd)!, and a failure becomes an exception. A command with a nonzero status raises CommandFailed, which holds the .status, the .stderr (a builtin's message; an attached program's goes to the terminal) and the .command. A Failed from ? raises its exception again. Anything else passes through, so (0)! is 0.

name = $(echo world)!
print hello $name
try
  (cd /no/such/folder 2>/dev/null)!
  print never
except CommandFailed as e
  print $e.command "->" $e.status
hello world
cd /no/such/folder 2>/dev/null -> 1

Nothing catching it, a CommandFailed stops the script with one line, tessh: build.tsh:4: Unhandled error: make failed (status 2), and the script exits with the command's status. The ! has to be glued to the ): ! cmd is still not, != still compares, and wow! is a word. For a chain put it after the part to check, a && (b)!, or around it all, (a && b)!. In a program's arguments, $(cmd)! and $(cmd)? are text, as in bash, so echo hi $(whoami)! prints hi ben!. To raise there, leave out the $: echo hi (whoami)!. Everywhere else, $(cmd)! is the operator: x = $(cmd)!, a line of its own, or a Python call's arguments.

Strict mode does that for every line, as bash's set -e does: after strict (or set -e, or tessh -e in the #! line, #!/usr/bin/env -S tessh -e), a program or pipe that fails on a line of its own raises CommandFailed. A failure something checks doesn't: ||, &&, if, ! cmd, r = (cmd). strict off (or set +e) ends it.

strict
false || print "checked, so it goes on"
try
  ls /no/such/folder 2>/dev/null
  print never
except CommandFailed as e
  print stopped at $e.command
strict off
false
print "off again"
checked, so it goes on
stopped at ls /no/such/folder
off again

Match

Barewords in a pattern match strings, $name captures, _ is anything.

def route cmd
  match $cmd
    case [go $dir]
      "going $dir"
    case [take *$items]
      "taking $items"
    case {kind: circle r: $r}
      "circle of $r"
    case (int) | (float)
      "a number"
    case [$n] if $n > 10
      "big $n"
    case _
      "what?"
print (route [go north])
print (route [take lamp key])
print (route {kind: circle r: 2})
print (route 3.5) (route [11]) (route [1])

Class patterns take positional or keyword sub-patterns, as $name names a part, and a dotted name matches a constant.

from dataclasses import dataclass
import enum
@dataclass
class Pt
  x: int
  y: int
class Color enum.Enum
  RED = 1
  BLUE = 2
def what v
  match $v
    case (Pt 0 0)
      'origin'
    case (Pt x=0 y=$y)
      "on the y axis at $y"
    case [1 2] as $whole
      "the list $whole"
    case Color.RED
      'red'
print (what (Pt 0 0)) "/" (what (Pt 0 5)) "/" (what [1 2]) "/" (what $Color.RED)
origin / on the y axis at 5 / the list [1, 2] / red
going north
taking ['lamp', 'key']
circle of 2
a number big 11 what?

Methods

As in Clojure, a word starting with . at the head of a call is a method: .name obj args… is $obj.name args…, the object first.

s = "  Hello  "
print (.strip $s) (.replace $s l L) (.count $s l)
print (.upper (.strip $s))
Hello   HeLLo   2
HELLO

.-name obj reads a field rather than calling it. A method you call for what it does stands on its own line.

import datetime
d = datetime.date 2024 3 9
print (.-year $d) (.isoformat $d)
words = [b a c]
.sort $words
print $words
2024 2024-03-09
['a' 'b' 'c']

Alone in parentheses, (.name) is a function that calls the method on its first argument, and (.-name) one that reads the field. (A bare .name as an argument is a word, since .bashrc is a file.)

up = (.upper)
print ($up hi) (list (map (.title) [ann bob]))
print (list (map (.-real) [1 2]))
HI ['Ann' 'Bob']
[1 2]

A .name stage in a pipe calls the method on what came in.

echo " a,b,c " | .strip | .split "," | print
['a' 'b' 'c']

Threading

-> value step… puts the value in as each step's first argument: (f a) becomes (f value a), and a bare step f or .name becomes (f value). ->> puts it in last. So methods chain with ->, and functions that take the collection last chain with ->>.

s = "  Hello World  "
print (-> $s .strip .lower (.replace world there) (.split " "))
print (->> [3 1 2] sorted (map $inc) list)
['hello' 'there']
[2 3 4]

Steps can go on indented lines.

r = ->> (range 10)
  filter (fn ($% % 2))
  map (fn ($% * $%))
  sum
print $r
165

Mix them by nesting a ->> step inside ->. (A .name step under ->> gets the value as its last argument, not as the object.)

print (-> "a-b" (.split "-") (->> (map $str.upper)) list)
['A' 'B']

some-> and some->> stop at the first None: the value is None and the later steps don't run.

cfg = {db: {host: "h1"}}
print (some-> $cfg (.get db) (.get host) .upper)
print (some-> $cfg (.get web) (.get host) .upper)
H1
None

as-> value name step… names the value, so it can go anywhere in a step; each step's result becomes the name's new value.

print (as-> [3 1 2] xs (sorted $xs) ($xs + [9]) (len $xs))
4

Doto

doto obj step… calls each step with the object first, then gives back the object itself. Steps can go on indented lines.

xs = doto []
  .append 1
  .append 2
  .extend [3 4]
print $xs
[1 2 3 4]

Let

let name=value … then a block (or a form on the same line) makes names that only that block sees, each bound in order, so a later one can use an earlier one. The value is the block's last form's. Outside it, a name of the same name is untouched.

x = outside
r = let x=2 y=($x * 10)
  $x + $y

print (let a=5 ($a * $a))
22 outside

Assigning to a let name in its block changes the block's own.

let total=0
  for n in [1 2 3]

Macros

Macros

A macro runs while the code compiles: it takes forms and returns forms. quasi with an indented template builds them; ~x inserts a form, ~@xs splices a list of them and $~x makes a variable from a name.

defmacro unless cond:expr *body
  quasi
    if (not ~cond)
      ~@body
x = 2
unless $x > 3
  print small
  print really
small
really

Parameters: name takes one item, *name the rest (indented lines included), and name:expr the rest of the line as one expression.

Macros are hygienic. Names a macro binds never clash with yours, and names it uses mean what they meant where it was defined.

defmacro swap a b
  quasi
    tmp = $~a
    ~a = $~b
    ~b = $tmp
tmp = 1
other = 2
swap tmp other
print $tmp $other
2 1

capture name breaks hygiene on purpose, for anaphoric macros.

defmacro aif cond:expr *body
  it = capture "it"
  quasi
    ~it = ~cond
    if $~it
      ~@body
aif (len [1 2 3])
  print got $it
got 3

:(form) is an inline template and ~(expr) inserts a value computed when the macro runs. Numbers, strings and lists a macro returns become literals.

defmacro twice x
  :(~x + ~x)
defmacro answer
  quasi
    ~(6 * 7)
print (twice 21) (answer)
42 42

Forms

quote form and :name are forms not evaluated. A macro gets its arguments as Form objects: .kind, .name, .items, .children, .value, .inner, .op, .bracket, indexing and len. str shows one as tessh.

f = quote (print a $b 1)
print $f.kind (len $f) $f[0].name $f[2].kind $f[3].value
s = :sym
print (str $f) $s.kind
Group 4 print Var 1
(print a $b 1) Sym

A macro can look at its forms and build code from them.

defmacro show_args *args
  names = [(str $a) for a in $args]
  quasi
    print ~names
show_args a $b (1 + 2)
['a' '$b' '(1 + 2)']

macroexpand shows what a form becomes, and gensym "hint" makes a fresh name (hygiene makes it rarely needed).

defmacro inc v
  quasi
    ~v = $~v + 1
print (str (macroexpand (quote (inc n))))
print ("tmp" in (str (gensym tmp)))
n = $n + 1
True

Macro code runs before the template: compute with the forms, then insert the results (~name for a name, ~(expr) for anything else). A name the macro makes for your code to use goes through capture; sym "name" makes a hygienic one and var s makes $s. Strings and numbers become literals.

defmacro getter name
  key = $name.name
  quasi
    def ~(capture "get_$key") obj
      $obj[~key]
getter color
print (get_color {color: teal})

Dependencies

need names PyPI packages a script, a cell or the REPL uses: uv installs them once into a cache, and they import from the next line. Quote a version range, so its > isn't a redirection.

The REPL

tessh alone starts the REPL: an editor for commands that works in any terminal (xterm, kitty, foot, tmux, ssh, the Linux console), with what Tessera's input editor has.

  • Enter runs what's complete. After a line that opens a block (def, if, for, x = if …, a macro) or with brackets or a string open, Enter starts a new line, indented for it; Enter on a blank line ends the block and runs it, as in IPython. An else, elif, except or finally typed too deep goes back to its if or try.
  • Alt+Enter (or Ctrl+J) adds a line anywhere. Tab in a line's indentation indents, Shift+Tab outdents, and Backspace there takes a whole level.
  • Tab completes names, programs, paths (quoted where they need it) and $ variables, in a list with each one's help beside it.
  • Colors are tree-sitter's, as in Tessera. The line under the input says what's wrong as you type (✗ unmatched ')'), the check tessh --check makes.
  • Grey text after the cursor is the newest command from history that starts with what's typed, or else the AI's guess (help ai): → or End takes it, Alt+F one word of it, Ctrl+Space takes it or asks the AI for one.
  • ↑ and ↓ go line by line, then through history; PgUp and PgDn a whole entry at a time; Ctrl+R searches it. History is kept in ~/.local/share/tessh/history, and ~/.config/tessh/rc.tsh runs first.
  • F1 (or Alt+H) shows help for the word at the cursor, or the keys on an empty line. Ctrl+Alt+J lists background jobs; Ctrl+Alt+D, the folders you have been in (cd history).
  • Ctrl+C interrupts, Ctrl+Z stops a program (fg brings it back), Ctrl+D exits. Emacs keys by default; TESSH_KEYS=vi for vi's.

Tessera's editor has keys on a tap of left or right Shift or Ctrl alone, and on Shift+Enter and Ctrl+Enter, which most terminals send as nothing or as plain Enter. Here they have keys every terminal sends:

The AI

# what you want, then Enter: the AI writes the command, and it waits in the editor for you to check and run (or change). As you type a # request, grey text finishes it, and after a pause → the command shows; → takes it. On other lines the AI's guess is the grey text when history has none.

tessh uses Tessera's AI settings when there are any (its providers, keys and models: the suggestion model for grey text, the chat model for requests). Without them, TESSH_AI_MODEL=provider/model picks one (ollama/qwen3.5:4b, anthropic/claude-…, openai/…, with the key in ANTHROPIC_API_KEY, OPENAI_API_KEY and so on), or else a local Ollama is used if one is running. TESSH_AI=0 turns it off.

The guide in a terminal

help guide (or tessh --guide) prints this whole guide, drawn for the terminal: headings, wrapped text, tables and highlighted examples. tessh --guide pipes prints one part, as help pipes does.

A tessh for any Linux

nix build github:benwbooth/tessera#tessh-static (or scripts/tessh-static.sh) makes tessh as one file that runs on any x86-64 or ARM64 Linux with nothing else installed: NixOS, a bare container, a server over ssh. scripts/tessh-static-macos.sh does the same for macOS (Apple Silicon or Intel). Ready-made ones are on the tessh-dev release (tessh-x86_64-linux, tessh-aarch64-linux, tessh-aarch64-macos, tessh-x86_64-macos) and on each Tessera release.

The Linux file carries uv and two builds of tessh (built against Python's stable ABI): one for glibc and one for musl, with musl's program loader. The first time it runs, it uses the glibc build when the system has glibc's loader and that build runs. Otherwise, as on Alpine or a bare container, it uses the musl build. It remembers the choice; TESSH_LIBC=gnu or musl forces one. Then it gets a CPython for that C library with uv (python-build-standalone's: about 30 MB to download, 93 MB unpacked) and keeps it under ~/.cache/tessh and uv's folder. On macOS it gets uv's macOS CPython the same way.

  • Which Python: tessh --python 3.14, TESSH_PYTHON=3.14, or a line in ~/.config/tessh/python; otherwise the newest one uv offers (3.12 or later), looked at once a day, so a new CPython in uv is taken up. A uv on PATH is used when it's newer than the one inside.
  • need numpy and --with install with uv, as everywhere: C extensions (manylinux or musllinux wheels: numpy, pandas, lxml) load as in any Python, since a real loader runs tessh. A package with no wheel for the system is built from source, which needs a C compiler.
  • Where uv can't tell the system's C library (a system with no dynamic loader at all, like a static busybox), tessh fetches the same CPython build directly.
  • python3 beside it in ~/.cache/tessh/rt-*/py/*/bin is that Python, for programs that want one.
  • No Windows build: tessh is built on Unix processes, signals and terminals. Under WSL, use the Linux file.

tessh as your login shell

tessh takes the flags a login shell gets:

  • -l or --login, or a - before its name (how login and sshd start one): first it imports the environment that /etc/profile, /etc/profile.d, ~/.profile and NixOS's set-environment set up, by running sh -l once. It doesn't take that sh's working folder or SHLVL. Then it runs ~/.config/tessh/login.tsh, before rc.tsh. A profile that takes more than 10 s is cut off, with a message.
  • -i: accepted, for programs that pass it. The REPL needs a terminal, so without one tessh runs stdin as a script.
  • -s [ARGS…]: run the script read from stdin, with ARGS as sys.argv[1:]. This also happens when stdin isn't a terminal and no file is given, as in cmd | tessh.
  • -c CMD: CMD is tessh code. One exception: when sshd starts tessh, as for ssh host cmd, scp, rsync or VS Code's remote server, CMD goes to /bin/sh, because those programs send sh commands. TESSH_SH_C=1 or 0 overrides this either way.

Short flags combine: tessh -li, or tessh -lc CMD, the same as -l -c CMD.

To make it your login shell, list it in /etc/shells first; chsh accepts only shells listed there. On NixOS, set environment.shells to include tessh (tessera.packages.${system}.tessh from this flake, or a path) and then users.users.<you>.shell. Elsewhere, add its full path to /etc/shells and run chsh -s /path/to/tessh. If ~/.profile runs exec tessh, that's fine: tessh notices it's being started while it reads the profile and doesn't start a second REPL.

Notebooks

In Tessera's notebook, tessh is the default kernel. A cell's last value shows with its richest form: HTML, Markdown, images, matplotlib figures. display x shows a value partway through, and input asks in the card. The folder and exported variables go back and forth with the pane's shell.

Programs a cell runs run in the pane's terminal, as a shell cell's do, with the cell's folder and variables. What they print goes in the card in order with the rest; a terminal app (vim, less, htop: one that takes the whole screen) gets the live terminal in the card while it runs. The cell goes on when it exits, with its status in $?.
